# 招聘管理系统 · 前端原型

依据《“招聘管理系统”项目管理概述》（`E:\recruit\1 项目管理概述-招聘管理系统.doc`）实现的前端页面与接口约定。

- 技术栈：**Vue 3 + Element Plus**（文档 1.2.2.1 指定），无构建步骤，浏览器直接运行
- 覆盖迭代：**迭代 1 用户与权限管理**、**迭代 2 职位管理**、**迭代 3 简历与候选人管理**、**迭代 4 招聘流程管理**
  （另附迭代 5 的「招聘漏斗数据看板」雏形）
- 接口文档：[`docs/接口文档.md`](docs/接口文档.md)
- 数据库设计：[`docs/数据库设计.md`](docs/数据库设计.md)（19 张表的建表脚本、ER 关系、索引要点）
- 数据：内置 Mock，接口路径/参数/响应结构与接口文档完全一致，后端就绪后一行开关即可联调

## 二、运行方式

## 六、界面设计取向：简单高效

界面刻意做了减法，让 HR 日常的「筛简历、约面试、发 offer」尽量少点击：

| 做法 | 具体表现 |
| --- | --- |
| 一屏看重点 | 看板只留 4 个决策指标（在招职位、候选人、今日面试、待入职），漏斗与投递 TOP5 并列，无装饰性图表 |
| 列表瘦身 | 每张表控制在 6～7 列，次要信息合并为主列的第二行小字（如「部门/城市」「学历/院校」） |
| 筛选收起 | 只把最常用的关键词 + 状态放在外面，其余筛选点「更多筛选」展开 |
| 高频操作直接点 | 职位行内直接「发布/下线」；流程行内直接点主推的下一步（如「通过筛选」），弹窗已预选好目标状态，只需确认；淘汰等分支收进「其他」下拉 |
| 少跳页 | 候选人、职位、投递详情都用右侧抽屉/弹窗完成，不打断当前列表 |
| 错误提示明确 | 状态流转非法、重复投递等由接口返回原因并直接提示，不出现"操作失败"这类模糊文案 |
| 表格密度可调 | 顶栏「紧凑/宽松」一键切换，一屏多看几行 |
| 响应速度 | Mock 延迟仅 50ms；列表只请求当前页，详情按需加载 |

## 七、与后端的联调

修改 `js/01-config-and-data.js`：

```js
const API_CONFIG = {
  baseURL: 'http://localhost:8080/api',  // 改成你的后端地址
  useMock: false,                        // 关闭 Mock
  mockDelay: 50
};
```

此时前端会以接口文档中的真实路径发起 `fetch` 请求，并自动带上
`Authorization: Bearer {token}`；后端返回 `code=401` 时前端会清除登录态并回到登录页。

## 八、约定说明

- **统一响应**：`{ code, message, data }`，`code=200` 为成功，前端直接使用 `message` 作为提示文案。
- **状态机**：招聘流程状态为 `1 待筛选 → 2 已通过筛选 → 4 待面试 → 5 面试中 → 6 面试通过 → 7 已发offer → 8 已入职`，
  分支状态 `3 已淘汰 / 9 已拒绝`；非法流转由接口拒绝，详见接口文档 7.7。
- **权限点**：登录响应返回 `permissions` 数组，前端用 `hasPerm('job:add')` 控制按钮显隐；
  `ADMIN` 视为拥有全部权限。
- **简历解析**：对应文档 1.1.3 定义，原型返回模拟解析结果，字段结构即为真实解析服务应返回的结构。

## 九、已知边界

- 本原型为**前端页面与接口契约**实现，数据存于浏览器内存，刷新页面后重置；上传的简历文件不落盘。
- 图表使用 CSS 进度条与表格绘制，未引入图表库；如需饼图/折线图，后端接口不变，前端可按需引入 ECharts。
- 迭代 5 的字典管理、系统参数、数据备份、趋势分析等接口已在接口文档第 13 节预留，页面待后续迭代补充。
