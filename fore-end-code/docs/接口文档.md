## 1. 通用约定

### 1.1 基础信息

| 项目 | 说明 |
| --- | --- |
| 协议 | HTTP/1.1（建议生产环境启用 HTTPS） |
| 服务地址（示例） | `http://localhost:8080` |
| 接口前缀 | `/api` |
| 数据格式 | 请求与响应均为 `application/json;charset=UTF-8` |
| 文件上传 | `multipart/form-data` |
| 鉴权方式 | 请求头 `Authorization: Bearer {token}` |
| 时间格式 | `yyyy-MM-dd HH:mm:ss`（日期字段为 `yyyy-MM-dd`） |
| 分页参数 | `pageNum` 从 1 开始，`pageSize` 默认 10 |
| 字符编码 | UTF-8 |

### 1.2 统一响应结构

所有接口（含失败）统一返回：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | int | 业务状态码，200 表示成功 |
| message | string | 提示信息，可直接展示给用户 |
| data | object / array / null | 业务数据；无返回数据时为 `null` |

### 1.3 业务状态码

| code | 含义 | 前端处理建议 |
| --- | --- | --- |
| 200 | 成功 | 正常渲染 |
| 400 | 参数校验失败 / 业务规则不允许（如非法状态流转） | `ElMessage.error(message)` |
| 401 | 未登录或登录已过期 | 清除 token 并跳转登录页 |
| 403 | 已登录但无权限 / 账号被停用 | 提示并回到有权限的首页 |
| 404 | 资源不存在 | 提示并返回列表 |
| 409 | 数据冲突（用户名重复、重复投递等） | 提示 message |
| 500 | 服务器内部错误 | 提示“系统繁忙，请稍后重试” |

### 1.4 分页响应结构

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "total": 46,
    "pageNum": 1,
    "pageSize": 10,
    "pages": 5,
    "list": []
  }
}
```

### 1.5 前端接入方式

原型内置 Mock 数据，接口路径、请求参数、响应结构与本文档完全一致。切换真实后端只需修改
`fore-end-code/js/01-config-and-data.js`：

```js
const API_CONFIG = {
  baseURL: 'http://localhost:8080/api',  // 后端地址
  useMock: false,                        // 置为 false 即请求真实接口
  mockDelay: 160
};
```

页面代码无需改动。`useMock: true` 时所有请求由 `js/02-api.js` 内的 Mock 调度器响应。

## 3. 认证与账号

### 3.1 登录

- `POST /api/auth/login`
- 权限：公开

请求体：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| username | string | 是 | 用户名 |
| password | string | 是 | 密码（明文传输需 HTTPS，后端建议 BCrypt 校验） |

```json
{ "username": "hr", "password": "123456" }
```

响应：

```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "hr",
    "tokenType": "Bearer",
    "expiresIn": 7200,
    "userInfo": {
      "id": 2, "username": "hr", "realName": "龚清", "avatar": "",
      "phone": "13800000002", "email": "hr@example.com",
      "deptId": 6, "deptName": "招聘组", "roleCode": "HR", "roleName": "HR/招聘专员"
    },
    "permissions": ["dashboard:view", "job:list", "job:add", "job:edit", "job:shelf"]
  }
}
```

失败：`401` 用户名或密码错误；`403` 账号已停用。

> 原型演示账号（密码统一 `123456`）：`admin` 系统管理员、`hr` / `zp` 招聘专员、`ms` 面试官、`cand` 应聘者。

### 3.2 应聘者注册

- `POST /api/auth/register`
- 权限：公开

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| username | string | 是 | 用户名，唯一 |
| password | string | 是 | 密码 |
| realName | string | 是 | 真实姓名 |
| phone | string | 否 | 手机号 |
| email | string | 否 | 邮箱 |

成功返回 `data` 为新用户 id；用户名已存在返回 `409`。

### 3.3 退出登录

- `POST /api/auth/logout`　权限：登录用户
- 响应：`{ "code": 200, "message": "退出成功", "data": null }`

### 3.4 获取当前登录信息

- `GET /api/auth/info`　权限：登录用户
- 用于刷新页面后恢复登录态。

```json
{
  "code": 200, "message": "操作成功",
  "data": {
    "userInfo": { "id": 2, "username": "hr", "realName": "龚清", "roleCode": "HR", "roleName": "HR/招聘专员", "deptId": 6, "deptName": "招聘组" },
    "permissions": ["dashboard:view", "job:list"]
  }
}
```

### 3.5 修改密码

- `PUT /api/auth/password`　权限：登录用户

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| oldPassword | string | 是 | 原密码 |
| newPassword | string | 是 | 新密码 |

原密码错误返回 `400`。

## 4. 系统管理：用户 / 角色 / 部门 / 日志

### 4.1 用户列表

- `GET /api/system/users`　权限：`system:user`

查询参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| keyword | string | 否 | 用户名 / 姓名 / 手机号模糊匹配 |
| roleId | long | 否 | 角色筛选 |
| status | int | 否 | 1 启用，0 停用 |
| pageNum / pageSize | int | 否 | 分页 |

列表项字段：`id、username、realName、roleId、roleName、deptId、deptName、phone、email、status、createTime`（不返回密码）。

### 4.2 新增用户

- `POST /api/system/users`　权限：`system:user`

```json
{
  "username": "hr02", "realName": "李四", "password": "123456",
  "roleId": 2, "deptId": 6, "phone": "13800000009", "email": "lisi@example.com", "status": 1
}
```

用户名重复返回 `409`；`password` 缺省时后端默认 `123456`。

### 4.3 修改用户

- `PUT /api/system/users/{id}`　权限：`system:user`
- 请求体同新增，`password` 为空表示不修改密码。

### 4.4 删除用户

- `DELETE /api/system/users/{id}`　权限：`system:user`
- 超级管理员（id=1）返回 `400` 不允许删除；其余返回 `data: true`。

### 4.5 启用 / 停用用户

- `PUT /api/system/users/{id}/status`　权限：`system:user`

```json
{ "status": 0 }
```

### 4.6 重置密码

- `PUT /api/system/users/{id}/password`　权限：`system:user`

```json
{ "password": "123456" }
```

### 4.7 角色列表

- `GET /api/system/roles`　权限：`system:role`
- 参数：`keyword`、`pageNum`、`pageSize`
- 列表项：`id、code、name、remark、status、permCount、userCount`

### 4.8 角色下拉（简表）

- `GET /api/system/roles/all`　权限：登录用户
- 响应：`data: [{ "id": 2, "code": "HR", "name": "HR/招聘专员" }]`

### 4.9 新增 / 修改 / 删除角色

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/system/roles` | `system:role` | 新增，`code` 唯一，重复返回 409 |
| PUT | `/api/system/roles/{id}` | `system:role` | 修改名称、说明、状态（`code` 不可改） |
| DELETE | `/api/system/roles/{id}` | `system:role` | 内置角色或角色下存在用户时返回 400 |

### 4.10 查询角色权限

- `GET /api/system/roles/{id}/permissions`　权限：`system:role`
- 响应：`data: ["job:list", "job:add"]`

### 4.11 分配角色权限

- `PUT /api/system/roles/{id}/permissions`　权限：`system:role`

```json
{ "permissions": ["dashboard:view", "job:list", "job:add"] }
```

### 4.12 权限点列表

- `GET /api/system/permissions`　权限：登录用户
- 响应：`data: [{ "code": "job:list", "name": "职位查看", "module": "职位管理" }]`

### 4.13 部门树

- `GET /api/system/depts/tree`　权限：`system:dept`
- 返回树形结构，顶级节点为企业信息：

```json
{
  "code": 200, "message": "操作成功",
  "data": [
    {
      "id": 1, "parentId": 0, "name": "示例科技股份有限公司", "leader": "陈静",
      "phone": "0755-88880000", "sort": 1, "status": 1,
      "children": [
        { "id": 2, "parentId": 1, "name": "技术中心", "leader": "李维", "sort": 1, "status": 1, "children": [] }
      ]
    }
  ]
}
```

### 4.14 新增 / 修改 / 删除部门

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/system/depts` | `system:dept` | 字段：`parentId、name、leader、phone、sort、status` |
| PUT | `/api/system/depts/{id}` | `system:dept` | `parentId` 不能等于自身，否则 400 |
| DELETE | `/api/system/depts/{id}` | `system:dept` | 有下级部门或部门下有用户时返回 400 |

### 4.15 操作日志

- `GET /api/system/logs`　权限：`system:log`
- 参数：`keyword`（对象 / 操作人 / 备注）、`module`、`pageNum`、`pageSize`
- 列表项：`id、module、action、target、operator、ip、remark、createTime`

## 5. 职位管理（迭代 2）

### 5.1 职位类别列表

- `GET /api/job/categories`　权限：登录用户
- 响应：`data: [{ "id": 1, "name": "技术研发", "sort": 1, "status": 1 }]`

### 5.2 新增 / 修改 / 删除类别

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/job/categories` | `job:category` | 名称唯一，重复返回 409 |
| PUT | `/api/job/categories/{id}` | `job:category` | 修改名称、排序、状态 |
| DELETE | `/api/job/categories/{id}` | `job:category` | 类别下存在职位时返回 400 |

### 5.3 职位分页查询

- `GET /api/jobs`　权限：`job:list`

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| keyword | string | 职位名称模糊匹配 |
| categoryId | long | 职位类别 |
| deptId | long | 所属部门 |
| status | int | 0 草稿 / 1 招聘中 / 2 已下线 / 3 已关闭 |
| city | string | 工作城市 |
| jobType | int | 1 全职 / 2 兼职 / 3 实习 / 4 劳务 |
| pageNum / pageSize | int | 分页 |

列表项字段：

```json
{
  "id": 1, "title": "高级Java开发工程师", "categoryId": 1, "categoryName": "技术研发",
  "deptId": 4, "deptName": "后端研发组", "jobType": 1, "jobTypeName": "全职",
  "city": "深圳", "salaryMin": 20, "salaryMax": 35, "headcount": 3,
  "eduReq": "本科", "expReq": "3-5年", "tags": ["Spring Boot", "MySQL"],
  "status": 1, "statusName": "招聘中",
  "publishTime": "2026-01-05 10:00:00", "deadline": "2026-02-20",
  "views": 386, "applies": 24, "applyCount": 24, "createBy": 2, "createTime": "2026-01-05 10:00:00"
}
```

### 5.4 职位详情

- `GET /api/jobs/{id}`　权限：`job:list`
- 在列表项基础上补充 `description`（岗位职责）、`requirement`（任职要求）。

### 5.5 新增职位

- `POST /api/jobs`　权限：`job:add`
- 新增即为草稿（`status=0`），发布需调用 5.7。

```json
{
  "title": "前端开发工程师(Vue3)",
  "categoryId": 1, "deptId": 5, "jobType": 1, "city": "深圳",
  "salaryMin": 15, "salaryMax": 25, "headcount": 2,
  "eduReq": "本科", "expReq": "1-3年",
  "tags": ["Vue3", "Element Plus"],
  "description": "1、负责管理端与门户前端开发；",
  "requirement": "1、熟练掌握 Vue3 组合式 API；",
  "deadline": "2026-03-01"
}
```

响应：`data` 为新职位 id。`title` 为空返回 `400`。

### 5.6 修改职位

- `PUT /api/jobs/{id}`　权限：`job:edit`
- 请求体同新增；`status` 不通过该接口修改。

### 5.7 职位上下架 / 关闭

- `PUT /api/jobs/{id}/status`　权限：`job:shelf`

```json
{ "status": 2, "reason": "岗位已招满" }
```

| status | 含义 | 规则 |
| --- | --- | --- |
| 0 | 转为草稿 | — |
| 1 | 发布（招聘中） | 已关闭（3）不可再发布，返回 400；首次发布写入 `publishTime` |
| 2 | 下线 | 可附 `reason` |
| 3 | 关闭 | 可附 `reason`，关闭后不可重新发布 |

### 5.8 删除职位

- `DELETE /api/jobs/{id}`　权限：`job:edit`
- 已收到投递的职位返回 `400`，提示改为下线。

## 7. 简历、候选人库与投递（迭代 3）

### 7.1 简历文件上传

- `POST /api/resume/upload`　权限：`resume:parse`（门户投递场景允许登录应聘者）
- `Content-Type: multipart/form-data`，字段名 `file`
- 限制：`.pdf` / `.doc` / `.docx`，其他格式返回 `400`

响应：

```json
{
  "code": 200, "message": "上传成功",
  "data": { "fileName": "王小明-个人简历.pdf", "fileUrl": "/files/resume/1737000000000.pdf", "fileSize": "320KB" }
}
```

### 7.2 简历解析

- `POST /api/resume/parse`　权限：`resume:parse`
- 对应文档 1.1.3“简历解析”：从 PDF/Word 中提取姓名、联系方式、学历、工作经历等并结构化。

```json
{ "fileName": "王小明-个人简历.pdf" }
```

```json
{
  "code": 200, "message": "简历解析成功",
  "data": {
    "candidateName": "王小明", "gender": 1, "age": 24,
    "phone": "13900000001", "email": "candidate1@example.com",
    "education": "本科", "school": "深圳大学", "major": "软件工程",
    "workYears": "1-3年", "latestCompany": "金蝶软件",
    "skills": ["Java", "MySQL"],
    "selfEval": "工作认真负责，具备良好的团队协作与学习能力。",
    "parseRate": 0.92
  }
}
```

### 7.3 投递简历

- `POST /api/applications`　权限：应聘者本人（管理端可由 HR 代录）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| jobId | long | 是 | 应聘职位 |
| candidateName | string | 是 | 姓名 |
| phone | string | 是 | 手机号，同一职位重复投递返回 409 |
| email | string | 否 | 邮箱 |
| gender | int | 否 | 1 男 / 2 女 |
| age | int | 否 | 年龄 |
| education | string | 否 | 学历 |
| school / major | string | 否 | 毕业院校 / 专业 |
| workYears | string | 否 | 工作年限 |
| latestCompany | string | 否 | 最近公司 |
| expectSalary | string | 否 | 期望薪资 |
| skills | string[] | 否 | 技能标签 |
| selfEval | string | 否 | 自我评价 |
| resumeName / resumeUrl | string | 否 | 简历文件（未上传时填“未上传简历”） |
| parsed | int | 否 | 是否已解析，0/1 |
| source | string | 否 | 官网投递 / 招聘网站 / 内部推荐 / 校园招聘 / 猎头 |

响应：`data: { "id": 50, "jobTitle": "前端开发工程师(Vue3)" }`，`message: "投递成功，请留意后续通知"`。
职位非招聘中（`status!=1`）返回 400。

### 7.4 投递记录 / 候选人列表

- `GET /api/applications`　权限：`resume:list` 或 `candidate:list`

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| mine | boolean | `true` 时仅返回当前登录应聘者本人的投递 |
| jobId | long | 应聘职位 |
| keyword | string | 姓名 / 手机号 / 院校 |
| status | int | 投递状态（见 7.7） |
| tagId | long | 候选人标签 |
| source | string | 简历来源 |
| education | string | 学历 |
| pageNum / pageSize | int | 分页 |

列表项：投递与候选人全部字段 + `statusName、statusType、tagList、interviewCount`。

### 7.5 投递详情

- `GET /api/applications/{id}`　权限：`resume:list` 本人或 HR

响应在 7.4 字段基础上追加：

```json
{
  "job": { "id": 2, "title": "前端开发工程师(Vue3)" },
  "interviews": [
    { "id": 3, "round": 1, "interviewTime": "2026-01-20 14:00", "method": 2, "address": "线上腾讯会议", "interviewerName": "李维", "result": 0 }
  ],
  "flowLogs": [
    { "id": 1, "fromStatus": 1, "toStatus": 2, "operator": "龚清", "remark": "简历符合岗位要求", "createTime": "2026-01-10 09:20:00" }
  ]
}
```

### 7.6 撤回投递

- `DELETE /api/applications/{id}`　权限：应聘者本人
- 仅 `待筛选(1) / 已淘汰(3) / 已拒绝(9)` 可撤回，其他状态返回 400。

### 7.7 投递状态字典与状态机

| status | 名称 | 可流转到 |
| --- | --- | --- |
| 1 | 待筛选 | 2 已通过筛选、3 已淘汰 |
| 2 | 已通过筛选 | 4 待面试、3 已淘汰 |
| 3 | 已淘汰 | 终态 |
| 4 | 待面试 | 5 面试中、3 已淘汰 |
| 5 | 面试中 | 6 面试通过、3 已淘汰 |
| 6 | 面试通过 | 7 已发offer、9 已拒绝、3 已淘汰 |
| 7 | 已发offer | 8 已入职、9 已拒绝 |
| 8 | 已入职 | 终态 |
| 9 | 已拒绝 | 终态 |

> 与文档 1.1.3“招聘漏斗”（简历投递 → 简历筛选 → 面试邀约 → 面试通过 → 录用）一致。
> 非法流转由接口返回 `400`，并在 `message` 中给出「当前状态 → 目标状态」。

### 7.8 候选人标签列表

- `GET /api/tags`　权限：登录用户
- 响应：`data: [{ "id": 1, "name": "重点推荐", "color": "#ef4444" }]`

### 7.9 新增 / 修改 / 删除标签

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/tags` | `candidate:tag` | 名称唯一，重复返回 409 |
| PUT | `/api/tags/{id}` | `candidate:tag` | 修改名称或颜色 |
| DELETE | `/api/tags/{id}` | `candidate:tag` | 同步从候选人身上移除该标签 |

### 7.10 设置候选人标签

- `PUT /api/candidates/{id}/tags`　权限：`candidate:tag`
- `{id}` 为投递记录 id（候选人以投递记录为载体）

```json
{ "tagIds": [1, 3] }
```

## 8. 招聘流程：筛选、面试、录用（迭代 4）

### 8.1 单条状态流转

- `POST /api/applications/{id}/flow`　权限：`flow:screen`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| toStatus | int | 是 | 目标状态，必须符合 7.7 状态机 |
| remark | string | 否 | 备注，淘汰时建议必填（记入操作日志） |

响应：`data: { "status": 2, "statusName": "已通过筛选" }`；非法流转返回 400。

### 8.2 批量状态流转

- `POST /api/applications/batch-flow`　权限：`flow:screen`

```json
{ "ids": [3, 4, 5], "toStatus": 2, "remark": "批量通过初筛" }
```

响应（逐条给出结果，便于前端提示失败原因）：

```json
{
  "code": 200,
  "message": "批量处理完成：成功 2 条",
  "data": {
    "total": 3, "success": 2, "fail": 1,
    "results": [
      { "id": 3, "success": true },
      { "id": 4, "success": true },
      { "id": 5, "success": false, "message": "当前状态为「已入职」，不可流转" }
    ]
  }
}
```

### 8.3 状态流转记录

- `GET /api/applications/{id}/flow-logs`　权限：`resume:list`
- 响应：`data: [{ "id": 1, "fromStatus": 1, "fromName": "待筛选", "toStatus": 2, "toName": "已通过筛选", "operator": "龚清", "remark": "...", "createTime": "..." }]`

### 8.4 安排面试

- `POST /api/interviews`　权限：`flow:interview`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| applicationId | long | 是 | 投递记录 id |
| interviewTime | string | 是 | `yyyy-MM-dd HH:mm` |
| duration | int | 否 | 时长（分钟） |
| method | int | 否 | 1 现场面试 / 2 视频面试 |
| address | string | 否 | 地点或会议链接 |
| interviewerId | long | 否 | 面试官 id |
| interviewerName | string | 否 | 面试官姓名 |
| notifyChannel | string | 否 | 短信+邮件 / 邮件 / 短信 / 电话 |

响应：`data: { "id": 22, "round": 1, "notifyChannel": "短信+邮件" }`；
安排成功后候选人状态自动流转为 `4 待面试`，并写入流转日志。`已淘汰/已入职/已拒绝` 状态返回 400。

### 8.5 面试列表

- `GET /api/interviews`　权限：`flow:interview` / `flow:evaluate`

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| applicationId | long | 指定候选人 |
| jobId | long | 指定职位 |
| interviewerId | long | 面试官 |
| result | int | 0 待面试 / 1 通过 / 2 未通过 |
| date | string | 面试日期 `yyyy-MM-dd` |
| keyword | string | 候选人 / 职位 / 面试官 |
| pageNum / pageSize | int | 分页 |

列表项：`id、applicationId、candidateName、jobId、jobTitle、round、interviewTime、duration、method、methodName、address、interviewerId、interviewerName、notifyChannel、notifyStatus、result、resultName、resultType、score、comment、status、createTime`

### 8.6 提交面试评价

- `PUT /api/interviews/{id}`　权限：`flow:evaluate`

```json
{ "result": 1, "score": 88, "comment": "技术基础扎实，沟通表达清晰，建议进入下一轮。" }
```

`result=1` 时候选人状态自动流转为 `6 面试通过`；`result=2` 时流转为 `3 已淘汰`，并记录评价到流转日志。

### 8.7 再次发送面试通知

- `POST /api/interviews/{id}/notify`　权限：`flow:interview`

```json
{ "channel": "短信+邮件" }
```

响应：`data: { "notifyChannel": "短信+邮件", "notifyTime": "2026-01-18 10:00:00" }`

### 8.8 开始面试

- `POST /api/applications/{id}/start-interview`　权限：`flow:interview`
- 将 `待面试(4)` 流转为 `面试中(5)`；其他状态返回 400。

### 8.9 录用列表

- `GET /api/offers`　权限：`flow:offer`
- 返回 `面试通过(6) / 已发offer(7) / 已入职(8)` 的候选人。
- 参数：`status`、`keyword`、`pageNum`、`pageSize`
- 列表项：`id、candidateName、jobTitle、score、status、statusName、statusType、offerSalary、entryDate、school、education`

### 8.10 发放 offer

- `POST /api/offers`　权限：`flow:offer`

```json
{ "applicationId": 12, "salary": "18K", "entryDate": "2026-02-10", "remark": "含三个月试用期" }
```

仅 `面试通过(6)` 可发放，否则返回 400；成功后流转为 `7 已发offer`。

### 8.11 确认入职

- `POST /api/applications/{id}/entry`　权限：`flow:offer`

```json
{ "entryDate": "2026-02-10" }
```

仅 `已发offer(7)` 可确认，成功后流转为 `8 已入职`。

### 8.12 记录候选人拒绝

- `POST /api/applications/{id}/reject`　权限：`flow:offer`

```json
{ "reason": "接受了其他公司 offer" }
```

仅 `面试通过(6) / 已发offer(7)` 可标记，成功后流转为 `9 已拒绝`。

## 9. 数据看板与统计

### 9.1 概览指标

- `GET /api/dashboard/overview`　权限：`dashboard:view`

```json
{
  "code": 200, "message": "操作成功",
  "data": {
    "jobTotal": 7, "jobOnline": 4, "resumeTotal": 37, "candidateTotal": 49,
    "interviewToday": 5, "offerPending": 4, "deptTotal": 6, "userTotal": 6
  }
}
```

| 字段 | 说明 |
| --- | --- |
| jobTotal / jobOnline | 职位总数 / 招聘中职位数 |
| resumeTotal | 已解析简历数 |
| candidateTotal | 候选人（投递）总数 |
| interviewToday | 今日面试场次 |
| offerPending | 已发 offer 待入职人数 |
| deptTotal / userTotal | 部门数 / 用户数 |

### 9.2 招聘漏斗

- `GET /api/dashboard/funnel`　权限：`dashboard:view`
- 参数：`jobId`（可选，按职位统计）

```json
{
  "code": 200, "message": "操作成功",
  "data": {
    "total": 49,
    "funnel": [
      { "stage": "简历投递", "status": 1, "count": 49, "rate": 100 },
      { "stage": "简历筛选", "status": 2, "count": 37, "rate": 75.5 },
      { "stage": "面试邀约", "status": 4, "count": 21, "rate": 42.9 },
      { "stage": "面试通过", "status": 6, "count": 12, "rate": 24.5 },
      { "stage": "录用入职", "status": 8, "count": 5, "rate": 10.2 }
    ],
    "interviewing": 9, "offers": 9, "hired": 5,
    "passRate": 75.5, "avgCycleDays": 15
  }
}
```

| 字段 | 说明 |
| --- | --- |
| funnel[].count | 到达该环节的候选人数（含后续环节） |
| funnel[].rate | 相对投递总量的转化率(%) |
| passRate | 简历筛选通过率(%) |
| avgCycleDays | 平均招聘周期（天） |

### 9.3 职位投递排行

- `GET /api/dashboard/job-rank`　权限：`dashboard:view`
- 响应：`data: [{ "jobId": 2, "title": "前端开发工程师(Vue3)", "views": 451, "applies": 31 }]`
