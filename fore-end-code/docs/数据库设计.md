## 2. 表关系（ER 概览）

```
sys_dept(1) ──< sys_user >── (1)sys_role ──< sys_role_permission >── (1)sys_permission
    │                                                                       ▲
    │ job.dept_id                                                           │ application.job_id
    └──────────────< job(1) ──< job_tag_rel >── tag_code                     │
                     │                                                       │
                     └──────────────< application >───────────────────────────┘
                                        │  ▲
                       candidate(1) ────┘  └──── (1)application_tag >── (1)tag
                            │
                            └──< resume

application(1) ──< interview
application(1) ──1 offer          （一条投递最多一条有效 offer）
application(1) ──< flow_log
```

关键关系：

- 一个 **部门**有多个用户、多个职位；一个 **用户**可有多角色（通过 `sys_user_role`）。
- 一个 **职位（job）** 对应多条 **投递（application）**；一条投递只针对一个职位。
- 一个 **候选人（candidate）** 可以投递多个职位，因此产生多条 `application`——这正是"候选人库复用"的关键。
- 一条 **投递** 有多轮 **面试（interview）**，最多一条 **offer**，多条 **流转日志（flow_log）**。

## 3. 建表脚本

### 3.1 企业与部门

```sql
CREATE TABLE sys_dept (
  id          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
  parent_id   BIGINT       NOT NULL DEFAULT 0      COMMENT '上级部门id，0=顶级公司',
  name        VARCHAR(64)  NOT NULL                COMMENT '部门/公司名称',
  leader      VARCHAR(32)           DEFAULT NULL   COMMENT '负责人',
  phone       VARCHAR(20)           DEFAULT NULL   COMMENT '联系电话',
  sort        INT          NOT NULL DEFAULT 1      COMMENT '排序',
  status      TINYINT      NOT NULL DEFAULT 1      COMMENT '状态：1正常 0停用',
  create_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  update_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_parent (parent_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='企业与部门（顶级节点代表企业信息）';
```

### 3.2 角色、用户与权限（RBAC）

```sql
CREATE TABLE sys_role (
  id          BIGINT      NOT NULL AUTO_INCREMENT,
  code        VARCHAR(32) NOT NULL COMMENT '角色编码：ADMIN/HR/INTERVIEWER/CANDIDATE',
  name        VARCHAR(64) NOT NULL COMMENT '角色名称',
  remark      VARCHAR(255)         DEFAULT NULL,
  status      TINYINT     NOT NULL DEFAULT 1 COMMENT '1启用 0停用',
  create_time DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  update_time DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_code (code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='角色';

CREATE TABLE sys_user (
  id          BIGINT       NOT NULL AUTO_INCREMENT,
  username    VARCHAR(32)  NOT NULL COMMENT '登录名',
  password    VARCHAR(100) NOT NULL COMMENT 'BCrypt 密文（切勿明文存储）',
  real_name   VARCHAR(32)  NOT NULL COMMENT '姓名',
  dept_id     BIGINT                DEFAULT NULL COMMENT '所属部门',
  phone       VARCHAR(20)           DEFAULT NULL,
  email       VARCHAR(64)           DEFAULT NULL,
  avatar      VARCHAR(255)          DEFAULT NULL,
  status      TINYINT      NOT NULL DEFAULT 1 COMMENT '1启用 0停用',
  last_login  DATETIME              DEFAULT NULL,
  create_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  update_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_username (username),
  KEY idx_dept (dept_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='系统用户（含应聘者账号）';

CREATE TABLE sys_user_role (
  user_id BIGINT NOT NULL,
  role_id BIGINT NOT NULL,
  PRIMARY KEY (user_id, role_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户-角色关联';

CREATE TABLE sys_permission (
  code   VARCHAR(48) NOT NULL COMMENT '权限编码，如 job:add',
  name   VARCHAR(64) NOT NULL COMMENT '权限名称',
  module VARCHAR(32) NOT NULL COMMENT '所属模块',
  sort   INT         NOT NULL DEFAULT 1,
  PRIMARY KEY (code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='权限点（对应接口文档 2.2 的 18 个权限）';

CREATE TABLE sys_role_permission (
  role_id         BIGINT      NOT NULL,
  permission_code VARCHAR(48) NOT NULL,
  PRIMARY KEY (role_id, permission_code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='角色-权限关联';
```

### 3.3 职位

```sql
CREATE TABLE job_category (
  id          BIGINT      NOT NULL AUTO_INCREMENT,
  name        VARCHAR(32) NOT NULL,
  sort        INT         NOT NULL DEFAULT 1,
  status      TINYINT     NOT NULL DEFAULT 1,
  create_time DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_name (name)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='职位类别';

CREATE TABLE job (
  id            BIGINT        NOT NULL AUTO_INCREMENT,
  job_name      VARCHAR(64)   NOT NULL COMMENT '职位名称（避免用 title 关键字，MySQL 8.0 有窗口函数 TITLE）',
  category_id   BIGINT        NOT NULL COMMENT '职位类别',
  dept_id       BIGINT                 DEFAULT NULL COMMENT '用人部门',
  job_type      TINYINT       NOT NULL DEFAULT 1 COMMENT '1全职 2兼职 3实习 4劳务',
  city          VARCHAR(32)   NOT NULL COMMENT '工作城市',
  salary_min    INT                    DEFAULT NULL COMMENT '薪资下限(K)',
  salary_max    INT                    DEFAULT NULL COMMENT '薪资上限(K)',
  headcount     INT           NOT NULL DEFAULT 1 COMMENT '招聘人数',
  edu_req       VARCHAR(16)            DEFAULT NULL COMMENT '学历要求',
  exp_req       VARCHAR(16)            DEFAULT NULL COMMENT '经验要求',
  description   TEXT                   COMMENT '岗位职责',
  requirement   TEXT                   COMMENT '任职要求',
  status        TINYINT       NOT NULL DEFAULT 0 COMMENT '0草稿 1招聘中 2已下线 3已关闭',
  publish_time  DATETIME               DEFAULT NULL COMMENT '首次发布时间',
  deadline      DATE                   DEFAULT NULL COMMENT '投递截止日期',
  views         INT           NOT NULL DEFAULT 0 COMMENT '浏览量',
  apply_count   INT           NOT NULL DEFAULT 0 COMMENT '投递量（冗余计数，便于列表展示）',
  offline_reason VARCHAR(255)          DEFAULT NULL COMMENT '下线原因',
  close_reason  VARCHAR(255)           DEFAULT NULL COMMENT '关闭原因',
  create_by     BIGINT                 DEFAULT NULL COMMENT '创建人',
  create_time   DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
  update_time   DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_category (category_id),
  KEY idx_dept (dept_id),
  KEY idx_status_publish (status, publish_time)   -- 门户"在招职位"列表主查询
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='职位';

CREATE TABLE job_tag_rel (
  job_id   BIGINT      NOT NULL,
  tag_name VARCHAR(32) NOT NULL COMMENT '技能标签，如 Spring Boot',
  PRIMARY KEY (job_id, tag_name)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='职位技能标签';
```

### 3.5 投递记录（招聘流程主线）

```sql
CREATE TABLE application (
  id            BIGINT       NOT NULL AUTO_INCREMENT,
  job_id        BIGINT       NOT NULL COMMENT '应聘职位',
  candidate_id  BIGINT       NOT NULL COMMENT '候选人',
  resume_id     BIGINT                DEFAULT NULL COMMENT '本次投递使用的简历',
  status        TINYINT      NOT NULL DEFAULT 1 COMMENT '1待筛选 2已通过筛选 3已淘汰 4待面试 5面试中 6面试通过 7已发offer 8已入职 9已拒绝',
  source        VARCHAR(16)           DEFAULT NULL COMMENT '本次投递来源',
  screen_remark VARCHAR(500)          DEFAULT NULL COMMENT '筛选/淘汰说明',
  score         INT                   DEFAULT NULL COMMENT '面试综合评分',
  apply_time    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '投递时间',
  update_time   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_job_candidate (job_id, candidate_id),  -- 同一职位不可重复投递（对应接口 409）
  KEY idx_status (status),                             -- 按状态筛选、看板漏斗统计
  KEY idx_apply_time (apply_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='投递记录（招聘流程状态机载体）';

CREATE TABLE application_tag (
  application_id BIGINT NOT NULL,
  tag_id         BIGINT NOT NULL,
  PRIMARY KEY (application_id, tag_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='投递-标签关联（候选人打标签）';
```

## 4. 关键设计说明

### 4.1 为什么"候选人"和"投递记录"要分两张表

文档要求"候选人信息重复、简历来源分散"是待解决问题。如果只有一张 `application` 表把简历字段全塞进去，同一个人投两个职位就会存两份简历，无法形成人才库。

- `candidate`：一个人只有一条，沉淀人才库，可被多个职位复用、打标签、二次触达。
- `application`：一次投递一条，承载流程状态（`status`）。
- 前端候选人库页面查 `candidate` 关联 `application`；投递记录页面查 `application` 关联 `candidate`。接口 7.4 返回的合并字段就是这两张表的联表结果。

### 4.2 状态字段是流程的唯一定义

`application.status` 的 9 个取值即接口文档 7.7 的状态机，**表结构不再存"环节"字段**，避免状态不同步。每次变更写一条 `flow_log`，这样页面上的"流程进度""流转轨迹"都能直接查出来。

### 4.3 冗余字段的取舍

| 冗余字段 | 位置 | 原因 |
| --- | --- | --- |
| `job.apply_count` | job | 门户职位卡片要显示"已投 N 人"，列表页逐行 count 会 N+1 查询 |
| `interview.interviewer_name` | interview | 面试列表高频展示，避免每次联 `sys_user` |
| `candidate.source` / `application.source` | 两张表 | 候选人首次来源 vs 本次投递来源，用于渠道转化分析 |

### 4.4 索引要点

- `application(status)`、`application(apply_time)`：看板漏斗与列表筛选。
- `job(status, publish_time)`：门户"在招职位"排序查询。
- `application(job_id, candidate_id)` 唯一键：既是防重复投递的业务约束，也是查询索引。
- `candidate(phone)`：HR 按手机号查重。

## 6. 初始化数据建议

系统首次启动需要写入：

1. **权限点**：接口文档 2.2 的 18 条，写入 `sys_permission`。
2. **角色**：ADMIN / HR / INTERVIEWER / CANDIDATE 四条，写入 `sys_role`。
3. **角色权限**：ADMIN 关联全部权限点；HR 关联职位、简历、候选人、招聘流程相关权限（可按接口文档 2.1 表格落库）。
4. **管理员账号**：`admin`，密码存 BCrypt 密文（演示环境明文为 `123456`）。
5. **企业与部门**：一条顶级公司记录（`parent_id = 0`），否则部门树为空。
6. **职位类别**：技术研发、产品设计、市场运营、职能支持四条起底数据。
7. **数据字典**：`job_type`、`application_status`、`edu_req`、`exp_req`、`source` 等，供迭代 5 的字典管理维护。
